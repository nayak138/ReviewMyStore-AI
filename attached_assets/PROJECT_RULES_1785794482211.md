# PROJECT_RULES.md
# ReviewMyStore.ai
## Engineering Rules & AI Coding Standards

### Purpose
This document defines mandatory engineering standards for any AI coding agent (Replit Agent, Cursor, Claude Code, Copilot) working on ReviewMyStore.ai.

---

# 1. General Principles

- Build for production, not demos.
- Prefer readability over cleverness.
- Do not duplicate business logic.
- Build one milestone at a time.
- Never leave partially implemented features.

---

# 2. Technology Stack

Frontend
- React
- TypeScript
- Tailwind CSS
- shadcn/ui
- React Router
- TanStack Query

Backend
- Node.js
- Express
- TypeScript

Database
- PostgreSQL (Replit Neon)
- Drizzle ORM

Validation
- Zod

Authentication
- JWT + Refresh Tokens
- bcrypt

AI
- Google Gemini

---

# 3. Folder Rules

- Business logic belongs in services.
- Controllers orchestrate requests only.
- Repositories handle database access.
- Shared types live in /types.
- Utilities live in /utils.
- Never place API calls inside UI components.

---

# 4. Database Rules

- Use UUID primary keys.
- Never hard delete business data.
- Use soft deletes where appropriate.
- Add indexes to frequently queried columns.
- Every business record must belong to an Organization.
- All migrations must be reversible.

---

# 5. API Rules

- Prefix all APIs with /api/v1.
- Return consistent JSON responses.
- Validate every request with Zod.
- Never expose stack traces.
- Use proper HTTP status codes.

---

# 6. Security Rules

- Validate all input.
- Enforce RBAC on every protected route.
- Never trust client-supplied organization IDs.
- Store secrets only in environment variables.
- Escape user-generated content before rendering.
- Rate-limit authentication and AI endpoints.

---

# 7. Frontend Rules

- Mobile-first.
- Accessible components.
- Loading, empty and error states for every page.
- Use reusable components.
- Keep pages thin.

---

# 8. UI Consistency

- Consistent spacing.
- Consistent typography.
- Consistent button styles.
- One primary action per screen.
- Use toast notifications for feedback.

---

# 9. AI Rules

- Gemini requests only from backend.
- Log prompt failures.
- Retry once on transient errors.
- Never fabricate review content.
- Customer can always edit AI output.

---

# 10. Performance

- Lazy-load routes.
- Paginate large tables.
- Cache expensive queries.
- Optimize images.
- Avoid unnecessary re-renders.

---

# 11. Git Workflow

- Commit after every completed milestone.
- Use meaningful commit messages.
- Never commit secrets.
- Tag MVP release as v1.0.0.

---

# 12. Testing

Before closing any milestone:

- Application builds successfully.
- No TypeScript errors.
- No ESLint errors.
- Authentication verified.
- Mobile UI checked.
- APIs tested.
- RBAC verified.

---

# 13. Code Review Checklist

Before merging:

- Is code reusable?
- Is validation complete?
- Is security enforced?
- Is tenant isolation preserved?
- Is documentation updated?
- Are analytics events tracked?

---

# 14. Definition of Quality

Every feature must include:
- Validation
- Error handling
- Loading state
- Empty state
- Analytics event
- Permission checks
- Responsive UI

---

# 15. Final Rule

Never sacrifice architecture for short-term convenience.

If a change improves maintainability without delaying the MVP significantly, prefer the cleaner design.
